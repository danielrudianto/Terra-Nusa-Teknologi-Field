# TerraBot Field — first-time setup on a PC

This repo contains the Dart code, the local `monotonic_clock` plugin, and two
hand-written Android files (`android/app/build.gradle.kts`,
`android/app/src/main/AndroidManifest.xml`). The rest of `android/` is
GENERATED by Flutter — step 2.

## 1. Flutter

Flutter stable **3.47** or newer (`flutter --version`). The packages in
`pubspec.yaml` need Dart 3.12.

Run every `flutter` command from a NORMAL PowerShell, not an Administrator
one. A Flutter SDK cloned as Administrator makes Android Studio fail with
"detected dubious ownership"; fix it with
`git config --global --add safe.directory C:/src/flutter`.

## 2. Generate android/

From the repo folder:

    flutter create --org id.co.alphakonstruksi --project-name terrabot_field --platforms android .
    del test\widget_test.dart

`flutter create` does NOT overwrite existing files, so the hand-written
Gradle file and manifest above survive. It also creates a counter-app
`test/widget_test.dart` that references a `MyApp` that does not exist —
delete it.

`android/` must contain only `.kts` Gradle files. If a Groovy
`settings.gradle` / `build.gradle` from an old Flutter version is present,
Gradle picks it first and fails with "applying Flutter's app_plugin_loader
Gradle plugin imperatively"; delete the Groovy files and run `flutter create`
again.

Add this line to `android/gradle.properties` (generated, so not in the repo):

    kotlin.incremental=false

Kotlin incremental compilation breaks on Windows when the repo (E:) and the
pub cache (C:) are on different drives ("this and base files have different
roots").

## 3. Packages & generated code

    flutter pub get
    dart run build_runner build

`build_runner` generates `lib/core/db/app_database.g.dart` (drift). Re-run it
whenever a table in `app_database.dart` changes.

## 4. Test

    flutter analyze
    flutter test

`test/cut_plan_test.dart` uses numbers from the Python prototype of the same
algorithm; if one differs, the formula has drifted.

## 5. Run on a device

Android 7.0+ phone with USB debugging, or an emulator. On an AMD CPU the
emulator needs SVM enabled in the BIOS and the Windows Hypervisor Platform
feature (`emulator -accel-check` must report WHPX usable).

    flutter devices
    flutter run --dart-define=API_URL=https://services.terrabot.alphakonstruksi.id

Local backend from the emulator: `--dart-define=API_URL=http://10.0.2.2:7500`.

The account is the same TerraBot web account. For the field menus to appear
it needs the **Field Engineer (Lapangan)** department (set on the web).
The server must have `sql/field-lapangan-v1.sql` applied — login writes the
new `refresh_tokens.perangkat` column.

## 6. Release APK

    flutter build apk --release --dart-define=API_URL=https://services.terrabot.alphakonstruksi.id

Release builds are signed with the TerraBot Field key (created 9 Oct 2026):

    android/key.properties                    passwords + alias (NOT in git)
    android/app/terrabot-field-release.jks    the key itself (NOT in git)

Back up BOTH files together in two places. Every update must be signed with
this same key: an APK signed differently cannot be installed over the app
on the phones, and uninstalling first deletes data that was not yet sent.
Without `key.properties` (another laptop) the build falls back to the debug
key — fine for trying, never for handing out.

Before each release: raise `version:` in `pubspec.yaml` (the number after
`+` must always go up). The app reports that version to the server; raise
`FIELD_MIN_APP_VERSION` in the server `.env` to lock out older APKs.
